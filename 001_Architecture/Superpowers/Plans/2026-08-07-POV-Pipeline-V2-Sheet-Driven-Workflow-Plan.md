# POV Shorts Pipeline v2 — Sheet-Driven Production Workflow Plan

## The locked 8-step process

1. **Research** the era/role/setting so details are historically accurate.
2. **Write the scene list** — what happens in each scene, in order, covering the whole story arc. (Say "scene," never "beat," when talking with Tony.)
3. **Run each scene through a physical-plausibility checklist** before finalizing its description:
   - Anatomy/pose check — does the described pose actually support the described action? (A person lying flat can't tie a shoe; sitting/kneeling is required.)
   - Camera-logic check — from true first-person, what would the camera actually see doing this action? State it explicitly before writing the prompt.
   - Difficulty triage — is this action inherently hard for the model (multi-limb tool interactions, ladder climbs, precise mechanical motion)? If so, substitute a simpler action that tells the same story beat instead of fighting the model.
   - Reference-conflict check — if a scene needs both an exact environment match *and* a pose different from an existing reference image, don't ask for both in one image-to-image call (the reference image's own composition tends to dominate/override a conflicting pose instruction). Pick one to anchor, let the other ride on fresh generation.
   - **Action-mechanics check — added 2026-08-07, gap identified after getting it wrong once already.** Verify the actual physical mechanism of the action, not just that an action is happening: which direction does it move, is it pushed or pulled, does it swing/lift/twist/slide, which hand/side does the work. Confirmed failure: a Roman Gladiator scene description said a door was "pushed open," but a door opened via a ring handle is pulled, not pushed — this went uncaught until Tony reviewed the generated image. The general anatomy/camera checks above did not catch this because they're framed at the pose/camera level, not the specific mechanical-direction level — this is a distinct check, not a duplicate of them.
   - **POV-visibility check — added 2026-08-08, distinct from difficulty triage.** Before writing any scene where another character makes physical contact with the POV character, verify the contact point is actually within a true first-person field of view (hands, forearms, chest-down at most). Never write contact with the POV character's own shoulder, back, top of head, or face — a body-worn camera at eye height cannot physically see those, mirrors aside, no matter how well the prompt is written. This is an optics fact, not a model limitation to prompt around. Confirmed failure: a Roman Gladiator scene described a fellow gladiator "clapping a hand on the POV character's shoulder" — the model, unable to render an invisible shoulder correctly, instead placed the hand on the POV character's knee with the leg raised at a wrong, confusing angle. Fix: rewrite the interaction to use a contact point that IS visible in true POV framing — a handshake, an object passed hand-to-hand, a nod with no touch at all.
   - **Body-position-must-be-explicit check — added 2026-08-08.** Any instruction involving "looking up" (or down, or to a side) must also explicitly state the character's overall body position (standing, sitting, kneeling, lying) — "looking up" alone is ambiguous between e.g. "standing, head tilted back" and "lying on the ground looking at the sky," which are completely different scenes. Confirmed failure: a victory scene meant to show the POV character standing with a fist raised, looking up at the crowd, was written as "arm raised, looking straight up and overhead" with no body-position stated — the model rendered him lying on the ground instead of standing.
4. **Write the scene description** for each scene — spatial/camera orientation included explicitly (which way is the character facing, what's to their left/right per the location's established geography), and any **featured extra** named directly in the text if they're recognizable and in direct contact with the POV character (e.g. "POV of main character shoveling coal with Sam and Walt").
5. **Build the reference sheets**, derived from the finalized scene descriptions (never built blind before scene descriptions exist):
   - **Featured Extra Character Sheet** — ONE sheet, every named recognizable extra who appears in direct contact with the POV character, built once, referenced by name wherever they appear again. Distinct facial features must be explicitly described per person in the prompt — do not leave facial distinctiveness implicit (confirmed failure: Sam/Walt and Alfred/George read too similar when not explicitly differentiated; Percy, who got more specific descriptive detail, worked).
   - **Background Extras Sheet** — a separate sheet, generic/unnamed examples ("Background Extra 1," "Background Extra 2," etc.), for wardrobe/era consistency only. For anyone facing away, deep background, or otherwise not identifiable by face — no individual identity consistency needed, so no per-person entry required.
   - **Environment Sheet(s)** — one per **location** (not per production), people-less (pure camera/room reference, no characters in frame), containing every distinct camera angle the *whole story* actually needs in that location — pulled comprehensively from the finalized scene descriptions, not built speculatively. **Corrected 2026-08-07 — no reuse across scenes at all, ever, even within the same room:** every single scene gets its own dedicated panel, one-to-one, with at least a slight nuanced variation in angle or zoom versus any other scene in that same location — a real human eye/POV is never locked to the exact same framing twice, so two scenes in the same room doing similar things still need visibly distinct panels (a few degrees up/down/left/right, or a slightly different zoom), not a shared "SCENE 4-5" merged panel. This replaces the earlier (now-wrong) "reuse when it's the exact same orientation" allowance — there is no legitimate reuse case; every scene number gets its own generation. Each panel labeled by its single scene number. **"People-less" means zero exceptions — corrected 2026-08-07:** no characters, humans, hands, arms, or held objects of any kind anywhere in an environment sheet, including distant/background/crowd figures. An early draft of the Roman Gladiator Colosseum sheet included distant crowd figures on the arena sand and hands on a door; both had to be regenerated out. (Practice dummies/mannequins are not people and are fine.) Environment sheets are pure empty-location camera references — every character, prop, and hand gets added later at step 6 by combining this sheet with the character/prop sheets.
   - **Main POV Character Sheet — do not forget this one.** Separate from the Featured Extra sheet. Covers the POV character's own build/skin tone/arms/legs (face usually irrelevant since it's rarely shown) for consistency across scenes. Confirmed gap 2026-08-07: this was skipped entirely on the first Roman Gladiator test pass with no deliberate reason — an oversight in executing this same checklist, not a design decision. Always build it alongside the Featured Extra sheet, never skip it.
   - **Framing must match the actual physical moment of the action, not its aftermath** — e.g. "pushing open a door" must be shown from the threshold with hands on the door, door still swinging, not skip ahead to "already inside, door open, looking back out." Confirmed failure: an early draft of the Roman Gladiator environment sheets merged Scene 4 (pushing open the armory door) and Scene 5 (already inside being armed) into one shared panel, which only depicted Scene 5's moment and silently dropped Scene 4's actual door-push action entirely.
   - **Prop Sheet(s)** — for the main POV character's own recurring handheld/closely-associated item(s) that stay in frame/focus often (a shovel, a pocket watch, a weapon, even a vehicle like a chariot). A featured extra's own prop is already covered by their entry on the Featured Extra Character Sheet (already shown in full costume/gear) — no separate prop sheet needed for them. Confirmed gap 2026-08-07: also skipped entirely on the first Roman Gladiator test pass alongside the main character sheet, same unforced oversight — always build it.
   - **Prop sheets need every orientation that could actually appear in a POV shot, not just one hero angle — added 2026-08-08.** A prop's "front" (the decorative/impressive side, the side that faces an opponent or an outside viewer) is often NOT what the POV camera ever sees — a held shield's front always faces away from the person carrying it, so true POV only ever sees the back/strap side with the forearm threaded through it. Confirmed failure: the Roman Gladiator Prop Sheet only showed the Scutum Shield's decorative front face with no back/strap-side reference and no "held from POV" reference; every scene needing the shield in-hand rendered it backwards/incorrectly because the model had nothing else to work from. Fix: for any prop with an asymmetric front/back or a specific carry/grip orientation, generate explicitly labeled panels for every side that could appear on screen — e.g. "Sword — Front," "Sword — Back," "Shield — Front," "Shield — Back (strap side)," plus at least one "held from POV" panel showing the actual grip/carry position.
   - **Sheet-generation method, confirmed 2026-08-07:** generate each environment sheet as ONE combined multi-panel image-generation call, not as individual per-scene images stitched together afterward. Checked both cost and consistency: GPT-Image-2 is priced per API call regardless of how many panels are described in one prompt (confirmed via the live model catalog — kie.ai $0.03/1K-image), so N individual calls cost roughly N times more than one combined call. Consistency-wise, one combined call also has an advantage — the model shares generation context across all panels in that call, which is likely why the combined sheets held together stylistically once dramatic-enough angle differences were specified; separate individual calls have no shared context with each other unless explicitly chained via reference images, which would add cost back on top. This is different from the storyboard step (step 6), which DOES generate individual full-resolution images — those are final production assets referencing the environment sheet by label, not disposable planning references, so the tradeoff is different there.
   - **Naming rule for all of the above:** never hardcode role titles (background worker / steward / first-class patron / gang boss / royalty / etc.) into pipeline code. These are freeform, per-production labels supplied at scene-writing time — a pyramid production has completely different roles than a Titanic production.
6. **Generate each scene's actual starting image** (the real first-frame image, later used as Seedance's `first_frame_url`) by attaching the **entire** Featured Extra Character Sheet, the **entire** relevant Prop Sheet, and the **entire** relevant location Environment Sheet as `input_urls` — whole images, never cropped — and, in the prompt text, naming the specific featured extra(s) by name and the specific environment angle by its scene-number label (e.g. "Sam and Walt from the attached cast reference... use the angle labeled Scene 5 from the attached environment reference"). **Never crop a panel out of a sheet.** Confirmed twice: (1) the Sam-and-Walt-in-the-boiler-room test (2026-08-07) — the whole 7-panel environment sheet was attached and the prompt named the label "MIDDLE RIGHT," producing a correctly-oriented result; (2) this is also how Scene 2's environment correction worked — the actual approved Scene 1 frame was attached whole (not cropped) as the reference. GPT-Image-2 reads and understands the full sheet as one asset and correctly locates the named/labeled element within it — cropping is unnecessary and was already shown to be unreliable for AI-generated multi-panel grids (unpredictable panel boundaries, resolution loss — the same reason storyboard panels are generated individually rather than sliced from one grid).
7. **Compile the storyboard sheet** — after all individual scene starting images already exist and are approved, assemble them into one combined sheet purely by deterministic, non-AI compositing (ffmpeg/PIL — this is what `storyboard_generation.py`'s `compose_contact_sheet()` already does). Each panel captioned with its scene number and a short description underneath, in plain composited text — never AI-generated text baked into an image (illegible/gibberish risk). This step is organizational only, for Tony's review — it does not feed back into generation.
8. **Generate the video for each scene via Seedance** using **only** that scene's starting image (`first_frame_url`) and the scene's action/sound description. **No character, environment, or prop sheets are fed into the Seedance video-generation call in v2** — the reasoning: the starting image already has everything (character, environment, props) baked in from step 6, and re-introducing sheet references at the video step risks adding confusion (e.g. Seedance trying to parse "who is George" from a sheet) rather than helping. The action/description driving the clip's motion is what should carry the shot, not sheet references. **Revisit this decision in a possible v3** — not before, and only with real test evidence.

## What this plan changes vs. the current built `Reimagined_Realms_POV_Shorts_Pipeline_v2/` code

Nothing has been implemented yet. When this gets built, expect changes to:
- `storyboard_generation.py` — needs to accept an environment-angle reference image per scene (not just character/environment sheets generically), and the per-panel generation call needs to combine environment-angle + character/prop sheet references together (already proven to work via the one-off tests, not yet wired into the actual script).
- `character_sheet_generation.py` — needs a distinct "Featured Extra Character Sheet" vs. a new "Background Extras Sheet" generator, with an explicit facial-distinctiveness instruction per person baked into the prompt-building logic, and no hardcoded role-title vocabulary.
- `environment_sheet_generation.py` — needs to move from "one combined sheet, guessed angles" to "one sheet per location, built from the finalized scene list, one panel per actually-needed angle, labeled by scene number, people-less."
- A new module for **prop sheets** doesn't exist yet at all.
- `video_generation.py` — confirm/lock that v2's Seedance call intentionally does NOT take character/environment/prop sheet references, only `first_frame_url` + prompt.

## Open items still not tested

- Whether reusing an environment-sheet angle panel across multiple scenes that need the exact same orientation actually holds up in practice (not yet tested — only tested generating one angle for one scene at a time so far).
- Whether the facial-distinctiveness fix (explicit per-person description) actually resolves the Sam/Walt/Alfred/George similarity problem — not yet re-tested since the note was made.
- Whether Seedance genuinely doesn't need sheet references at the video step, or whether this just hasn't been tested with a real video generation yet (2026-08-07 test only covered image generation, not video).

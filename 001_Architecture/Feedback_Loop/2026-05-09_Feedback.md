# Feedback Log — 2026-05-09

## [3:41 AM] Filename Quality Enforcement — Visual Assets Pipeline

**What happened:** After running the full ingest pipeline (54 files, then PDF/Screenshot/Video batches), ~130+ files ended up in Visual_Assets with non-descriptive or random-string filenames. Patterns found: `Screenshot-*` (~30 files), `Clip-1` through `Clip-8`, `ChatGPT-Image-TIMESTAMP-*` (~11), `BN-Post-Idea*`, `Conference-Floorplan-Adobe-Vizrt-*` (~16), `Job-Boards-*` (~10), `Digital-Products-Social-Media-*` (~16), `Forms-And-Models-*` (~14), `Cross-X-Prompt*`, and various random hex strings.

**Tony's correction:** "That should always be enforced — check the script or the skill to make sure that's enforced. There should never be random strings in the name. If there's a log (because there should be a log that shows which file names were changed), that would be a way to find this. You have to update all the .md asset notes for anything that is a name change."

**Root causes identified:**
1. `process_image_ingest.py` accepts whatever `title_case_name` the AI returns — no validation that the name is actually descriptive. AI sometimes returns generic names like "Screenshot-Tool" or "Image-Reference" when it can't fully read the image.
2. `check_vision_needed.py` lookup-first gate only checks the asset note `ai_description` for filler text — does NOT check whether the filename itself is descriptive. Files with bad names but OK descriptions pass silently.
3. No rename log existed, making it impossible to audit what was renamed vs. what was always bad.
4. Rename operations did not update paired asset notes.

**Fixes applied this session:**
- `process_image_ingest.py`: Added `validate_title_case_name()` function with bad-pattern list; files with invalid names route to `Undetermined/` instead of Visual_Assets
- `check_vision_needed.py`: Added `is_bad_filename()` function checking for Screenshot*, Clip-N, ChatGPT-Image-*, hex strings, single generic words; bad-filename files flagged even if asset note passes filler check
- Rename log added at `Visual_Assets/rename_log.md` (written by process_image_ingest.py on every move)

**Resolved:** All bad-named files re-visioned across two batches (51 files AM, 162 files PM). 834 Title-Case images confirmed in Visual_Assets.

## [1:40 PM] Multi-Agent Pipeline Coherence Audit — Findings and Fixes

**Context:** After completing the 185-file re-vision batch, Tony requested a cross-model audit of the entire image ingest pipeline to surface contradictions before they cause future breakage. Gemini (large-context coherence pass) + Claude embed scanner run in parallel.

**Critical findings from Gemini audit:**

- **C4 (BLOCKING):** `check_vision_needed.py` had `ASSET_NOTES_DIR` pointing to `007_Resource_Library/Asset_Notes` — a directory that doesn't exist. `process_image_ingest.py` writes notes to category folders (`Tools/`, `Research/`, etc.). The lookup-first gate was completely broken — always reporting "no asset note" even for fully-processed files.
- **C3:** `check_vision_needed.py` read `ai_description:` frontmatter field, but notes written by `process_image_ingest.py` use `## AI Analysis` section body. Gate never found a valid description.
- **C1:** SKILL.md and TOOLBOX.md both said "Gemini vision first" — actual script uses OpenRouter (qwen model) with OpenAI fallback. No Gemini used anywhere in the pipeline.
- **C2:** `process_image_ingest.py` PROMPT asked AI to return `kebab_case_image_name` in JSON, but file-move logic only used `title_case_name`. Dead field caused AI confusion about which format to return.
- **C5:** `rename_screenshots.py` (legacy) explicitly prompts for lowercase kebab-case names and calls Gemini API directly — completely incompatible with current pipeline. No deprecation notice existed.
- **G13:** `fix_image_case.py` docstring advertised `--since` flag that was never implemented.
- **Embed scanner:** 3,253 total broken embeds in 1,894 notes. 551 wrong-case (file exists, embed string uses wrong case) — fixable by script. 2,702 not-found (files semantically renamed or never ingested).

**Fixes applied (all in this session PM):**
- `check_vision_needed.py`: Replaced `ASSET_NOTES_DIR` → `RESOURCE_LIBRARY` + `CATEGORY_FOLDERS`; `get_note_path()` → `find_note_path()` searching all category dirs; `read_ai_description()` now reads `## AI Analysis` section; added uppercase IMAGE_EXTENSIONS variants
- `process_image_ingest.py`: Removed `kebab_case_image_name` from PROMPT JSON spec; fixed bad-name log message; added md_path conflict guard (counter suffix on note name)
- `SKILL.md`: "Gemini vision first" → "OpenRouter vision first (qwen model)"; "kebab-case" → "Title-Case-With-Dashes" in File Naming footer and Step 3
- `TOOLBOX.md`: Updated process_image_ingest.py description (OpenRouter), updated check_vision_needed.py description (category folders), added fix_image_case.py entry
- `rename_screenshots.py`: Added deprecation header pointing to process_image_ingest.py
- `fix_embeds.py` (new script): Fixed all 549 wrong-case `![[]]` embeds across 549 notes

**What to do about 2,702 not-found embeds:** These reference images that were semantically renamed (embed still uses old name) or were never ingested. Requires manual review or matching by content — not auto-fixable. Tony to decide next steps.

## [3:41 AM] Persistent Failure Pattern — "Not Doing Your Checks"

Tony: "This is a very important learning step in your feedback loop in your memory because these are the types of errors I don't want to have to repeat or keep reiterating because I see them continuously happening so you're not doing your checks."

**Pattern:** Completing a task (ingest, vision, rename) without verifying the output quality. Marking work as done when the task ran, not when the output was validated.

**Required behavior:** After any pipeline run (ingest, image processing, rename), always spot-check a sample of output filenames, descriptions, and routes before declaring completion. If quality checks aren't built into the script, add them before running.

## Graphify rebuilds — Codex offload (validated approach)

Claude's account hit its session rate limit 4+ times overnight running graphify
semantic-extraction subagents. **Validated:** handing a whole graphify domain build
to Codex via `Skill("codex:rescue")` with a written spec file works cleanly —
separate quota, no Claude rate-limit pressure, Codex followed the graphify SKILL.md
procedure fine and wrote a completion report. Use this as the default for
heavy graphify domain builds going forward, not Claude subagents.

**Why:** graphify's per-chunk semantic extraction fans out to many parallel LLM
calls (100+ for a big domain); that's exactly the burst pattern that trips the
session limit. Codex has independent quota and the extraction task is generic
enough (read files → emit graph-fragment JSON per schema) that it doesn't need
Claude specifically.

**Also learned:** a Claude subagent dispatched via the Agent tool CANNOT reliably
receive async background-task completion notifications the way the primary session
does — a subagent that "dispatches sub-subagents and waits for a notification"
gets stuck in a re-poll loop that never completes. Either have subagents run their
child work synchronously within their own turn, or don't nest that pattern —
dispatch the leaf work directly from the primary session.

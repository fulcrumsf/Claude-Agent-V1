# Feedback — 2026-08-22

## New standing rule: grade every finished video
Tony's explicit instruction: every finished video (full assembled cut, not individual scenes) gets a letter grade logged, building a self-learning database over time. First entry: `0002_Mantis_Shrimp_Color_Vision` FINAL_v1 = **B- / B**. Log location: that production's `Data/Report_Card.md` (already has a `Grade`/`Previous Grade`/`Review Date` structure — use it going forward for every production, not just this one). Do this automatically at the end of every production, don't wait to be asked.

## Confirmed approach: scene-by-scene manual validation before autonomy
Tony explicitly framed this session as testing the pipeline: work scene-by-scene, review each one, target ~95% confidence before letting later phases run more autonomously. This is a validated, repeatable working style for this channel's productions — not a one-off. Don't skip straight to batch-generating a whole production without this review cadence unless Tony says otherwise.

## Confirmed: storyboard is the source of truth over a stale shot list
Multiple times this session, `Shot_List.md` entries didn't match their own storyboards (written before the storyboard, or before a rule like Approach B was locked). Tony's instruction each time: trust the storyboard, rewrite the shot list to match — never the reverse. Apply this check automatically at the start of any scene work, don't wait for Tony to notice the mismatch.

## Confirmed: creature coloration stays fixed, only atmosphere/lighting varies for visual distinctiveness
When Tony wanted scenes to feel visually distinct from each other (not repetitive), he explicitly rejected the idea of varying the creature's own skin color — asked whether it was biologically accurate first, and once told no (no real cold/warm-water color morph for this species), settled on varying water clarity/color grade/lighting mood instead. General principle: check the biology/facts before making a creative call that could read as a factual claim, and when in doubt vary environment/atmosphere before touching the documented subject itself.

## Confirmed: real per-component matting method matters more than a fixed default
Chroma-green is not a universal "safe default" — it actively contaminates translucent/glowing assets (color spill visible after matting) even though it works cleanly on opaque ones. Caught by compositing over an actual checkerboard test pattern, not just eyeballing the RGBA file — that verification step is what surfaced a defect that would've been invisible in a casual look. Apply this checkerboard-composite check to every matted asset going forward, not just when something looks off.

## Not yet resolved: what "assembly" means for this channel going forward
The full pipeline's Phase 7 calls for a hand-authored Remotion master composition per production. This session's assembly used direct ffmpeg concat + audio mixing instead — got the B-/B grade partly because of this gap. Tony hasn't said which approach is the actual standard going forward; flag this as an open question next time assembly comes up, don't assume ffmpeg-concat is now acceptable as a permanent shortcut.

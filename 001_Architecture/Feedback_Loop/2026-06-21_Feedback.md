# Feedback — 2026-06-21

## [CORRECTION] Price Columns Must Show Actual $/s — No Normalization
**What happened:** I synced a new Airtable table but the price columns showed per-5s-clip normalized values ($1.75 for Veo 3.1 instead of $0.35/s, $1.55 for Seedance instead of $0.31/s). Tony caught it immediately.

**Tony's words:** "I don't care if you have to convert it because you have to figure out the units or if the price is telling you it's for a 5-second generation — you have to divide it by 5 or whatever the case. Everything needs to be per-second cost."

**Rule:** Every platform price column in the Model Catalog shows the actual cost per unit of output — $/s for video, $/img for images. Never show a normalized "per-clip" value. If a price is quoted per N seconds, divide by N before displaying. If the duration is unknown, mark it as X or note the assumption.

**Why:** Tony is comparing platforms visually in Airtable. A multiplied/normalized number is misleading and not what he asked for. This is a recurring frustration.

## [CORRECTION] Resolution Must Be Visible in the Row Name
**What happened:** New variant rows had a `Resolution` column, but the default Airtable view didn't surface it prominently. Tony couldn't tell which row was 720p vs 1080p at a glance.

**Rule:** When a model has multiple resolution variants, append `(Resolution · Audio)` to the Name field so it reads like `Seedance 2.0 (1080p · Audio)`. Don't rely on a separate column being visible.

## [VALIDATED] Per-Second Table Structure
Tony confirmed the restructured table (34 variant rows, $/s prices, Name with resolution) is correct. No pushback on the variant-per-row design or the X cells for unsupported resolutions.

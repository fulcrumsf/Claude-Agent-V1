## POV Shorts caption conventions (corrections)

Tony corrected two things on the first real POV Shorts render (Pyramid Builder I. Deep, production 0003):

1. **Opening title must state the actual subject, never a literal blank.** "POV: You Wake Up As An Egyptian Pyramid Builder", not "POV: You Wake Up As A ___". Why: YouTube Shorts auto-grabs an early frame as the thumbnail — a blank placeholder becomes the literal thumbnail text and defeats the hook.
2. **All captions move to the top ~18% of frame** (was mid-screen/bottom). Why: that's where the eye is drawn first on Shorts/Reels/TikTok, and it stays clear of platform UI overlaying the bottom of the screen on all three.
3. Follow-up correction: **the opening title must be fully opaque on the literal first frame, not mid-fade-in.** Same root cause as #1 — the auto-thumbnail grab. Fixed by giving frame-0 captions a zero-length fade-in in `POVCaption.tsx` while every other caption keeps its fade.

All three applied directly to `POVCaption.tsx` and `POV_Style_Guide.md`, commits `54ae664` and `0dc8874`. Full detail in Claude memory: `feedback_pov_shorts_caption_conventions.md`.

## Validated approach: real production run before further pipeline stages

Tony confirmed ("okay great" / no pushback) the sequencing: build Assembly + Text-Overlay first, then run one real, full end-to-end production ("Pyramid Builder I. Deep") rather than continuing to build unbuilt stages (YouTube trend-research ideation, YouTube package) speculatively. The critique-and-iterate loop on a real output surfaced concrete, high-value fixes (caption content/position/timing) that abstract planning wouldn't have caught. Confirms the project's existing bias toward "ship one real thing, then iterate" over building every stage before testing any of them.

## Graphify: never process video or images

Tony gave a hard, durable rule when the Video Editor domain graphify build tripped its own cost gate (979 files / 7.8M words, almost entirely binary media): "graphify should never really process any images or videos. It just needs to know how all that stuff connects... from an architecture standpoint." This is now enforced via a repo-root `.graphifyignore` (see Global_Agent_Memory.md and the reference memory file for the mechanics — the tool reads `.graphifyignore` at the repo root and ancestor dirs, NOT `.graphify/.graphifyignore` as REGISTRY.md had incorrectly documented; both are now fixed).

# Feedback - 2026-05-01

## Correction: Suspicious pasted npm commands
- Tony clarified he was not trying to update or install the Remotion component path that appeared in a pasted Codex update command.
- If a command intended to update Codex includes an unrelated workspace source-file path, especially a `.tsx` file, treat it as suspicious and clarify before executing.
- Correct Codex npm package target is `@openai/codex`, not project-local source files.

## Preference: Shift+Enter for multiline agent prompts
- Tony prefers `Shift+Enter` as the single, memorable command for adding new lines in terminal-based agent prompts.
- When configuring Codex, Claude Code, or similar terminal agents inside IDE terminals, preserve `Shift+Enter` for multiline input when the terminal supports it.

## Validated: Codex Shift+Enter multiline fix
- Tony confirmed `Shift+Enter` now adds another line inside the Codex terminal session.
- Working setup uses both layers: Antigravity terminal keybinding sends `\u001b[13;2u`, and Codex config maps `tui.keybindings.insert_newline = "shift-enter"`.

## Preference: Pastel numbered workspace folder icons
- Tony considers folders beginning with a three-digit number and underscore, such as `001_Architecture`, to be top-level workspace departments.
- These department folders should be visually color-coded in Antigravity Explorer with nice-looking pastel colors.

## Validated: Antigravity local extension install requires a packaged VSIX
- A raw extension folder in `~/.antigravity/extensions/` is not enough for reliable installation.
- To register a local Antigravity extension, package it as a `.vsix` with `extension/package.json` inside the archive, then install it with the Antigravity CLI.
- Antigravity records installed extensions in `~/.antigravity/extensions/extensions.json`.

## Validated: Full Explorer row coloring needs CSS injection
- A file icon theme can color folder icons, but not the whole Explorer row background.
- For per-folder row backgrounds in Antigravity, use a CSS injection extension such as `be5invis.vscode-custom-css` and target the Explorer tree rows with CSS selectors.

## Validated: Ingest should recurse into subfolders by default
- Tony confirmed the ingest skill should process all files in subfolders within `000_Ingest/` without needing to be told.
- Exception: if Tony specifies "top-level only" or a single file.

## Preference: PDFs don't need an Asset Note
- Obsidian has a native PDF viewer, so PDFs are readable directly.
- Route PDFs to `007_Resource_Library/Docs/` with no companion file.
- Only create a wiki page for PDFs if the content is worth synthesizing.

## Preference: Asset Notes go in a dedicated folder, not alongside the media
- Tony wants `007_Resource_Library/Asset_Notes/` as the home for all companion `.md` files.
- Asset Notes are named identically to the media file (same stem, `.md` extension).

## Preference: Notion database scaffolding is noise, not content
- When Notion databases are exported, the top-level container `.md` files (the database "index" pages) have no real content value.
- Tony will delete these manually before running ingest.
- The ingest skill should skip any `.md` file that is clearly a Notion database container (only metadata, no real content).
- Individual record `.md` files inside a Notion export should be ingested normally.

## Correction: Always check existing Asset Notes before calling vision

- When ingesting images or any file requiring vision, first run `check_vision_needed.py` to audit Asset Note quality.
- Do NOT call the rename script or any vision API until the lookup-first gate confirms the file lacks a real description.
- Filler patterns that indicate vision is needed: "likely a saved reference", "general visual reference", "This appears to be a screenshot of…", description under 60 chars, or no Asset Note.
- Codex ran ingest on 580 images without vision access and produced boilerplate Asset Notes — all 580 flagged as needing real vision. This is the failure mode the lookup-first gate prevents going forward.

## Preference: Asset Notes must contain specific, observable content

- A proper Asset Note for an image must include: what platform it's from (TikTok, Instagram, GitHub, etc.), what specific information is visible (tool name, tour dates, prices, chart data, etc.), and why Tony likely saved it.
- Generic descriptions like "a saved reference for Tony's research" have zero recall value and should be treated as failures.
- Good example: "Instagram Reel screenshot showing Spain Tour 2025 dates — 9 venue/date entries listed."

## Validated: The CSS loader needs the workbench HTML patch
- Installing `be5invis.vscode-custom-css` and setting `vscode_custom_css.imports` is not enough by itself.
- Antigravity loaded the Explorer row stylesheet only after the workbench HTML at `/Applications/Antigravity.app/Contents/Resources/app/out/vs/code/electron-browser/workbench/workbench.html` was patched to inline the stylesheet.

## Preference: Execute Heavy API Loops Outside of Claude Code
- Claude Code orchestrates and writes scripts using Anthropic tokens. Large processing loops (like scanning 500+ images) should be offloaded to standalone scripts or Gemini CLI.
- This prevents Claude Code from locking up due to Anthropic API org limits.

## Preference: Vision Must Read Text and Context, Not Just Visuals
- When analyzing screenshots of tools or UI, the AI should explicitly look for text in the image (like specific tool names, e.g., "QWEN Image Edit Camera Angle Control") to categorize it correctly.
- Do not just output generic descriptions of shapes and colors for app screenshots. Use the text to infer the business context.

## Session: Anomalous Wild motion graphics critique + Vox-style asset architecture brainstorm (Jul 6, 2026)

### "AI slop" definition, precisely — abstract data-viz is fine, missing illustrated grounding is not
Tony reviewed the Bioluminescence Weapon video's phylogenetic-tree section (1:38–2:14, `final_render_V4.mp4`) via `gemini_scene_analysis.py`. His verdict: the dots-and-lines tree animation itself is NOT the problem — it's fine as a structural/data-viz layer. The problem is that while narration names specific organisms (fish, squid, jellyfish, fungi, beetles, bacteria), the visual never shows illustrated overlays of those organisms tied to the dots. The abstract graph has nothing concrete for the viewer to visually anchor to. That gap — narration naming a concrete thing, visual staying abstract — is his working definition of "slop" for motion graphics going forward. Applies to any future Vox-style/explainer motion graphic: every named subject in narration should get a corresponding illustrated visual reference, not just an abstract data shape.

**Root cause found (not a model-quality failure):** The video's own `Script.md` (line 113) explicitly specified the abstract tree-and-dots treatment in its VISUAL direction — it never called for illustrated creature overlays in the first place. The build executed the script's direction correctly; the script itself under-specified the visual. Future scripts for this kind of scene need the VISUAL line to call out specific illustrated assets per named subject, not just "phylogenetic tree, glowing dots."

### Architecture preference: orchestrator + specialized agents, not one skill doing everything
Tony explicitly does not want a single skill responsible for both directing the motion graphic AND generating the illustrated assets AND animating them — his words: "I don't want the one skill to have too many tasks that it does shortcuts on." Preferred shape: a motion-graphics orchestrator (director) that identifies what assets are needed for a scene and delegates asset creation to a dedicated, specialized sub-agent (e.g., "go make me an illustrated beetle asset, no text, matching X style"), then handles composition/animation itself. This mirrors the existing Reference-First Pipeline already documented in `002_Content-Creation/Video_Editor/CLAUDE.md` (Nano Banana illustration → Figma/SVG labels → Remotion static asset) — the fix is applying that same asset-first discipline to Vox-style explainer motion graphics, not inventing a new pattern.

### Case-Study-Analysis skill does not transfer visual taste into generation
Tony built the case-study skill specifically hoping curated reference screenshots (of videos he liked) would teach future generation what "good" looks like. It didn't work — output was still slop. Root cause: `Case-Study-Analysis.md` is a performance/growth analysis framework (viral score, hook strategy, retention, benchmarking) — its "Visual Elements" section is a shallow checklist line, not a deep style reference, and nothing in the actual asset-generation workflow re-consults those screenshots at build time. A reference-library-for-generation mechanism (hand a real example image directly into context at generation time, not cited in a written doc) is a distinct, unbuilt need — do not assume the case-study skill already covers this.

### Test protocol proposed for closing the "taste" gap (not yet run)
To isolate whether current models can hit real Vox/Kurzgesagt-level illustration fidelity: give a single real reference frame directly as an image in-context, ask for one static illustrated asset matching it, and grade side-by-side before investing in a full pipeline rebuild. Cheap, fast signal before committing to bigger architecture.

### One-off test: GPT Image 2 → Seedance 1.5 "tree of life" intro beats a bare data-viz open (DEFERRED — not implemented, do not build yet)
Ran a second, separate one-off test: for scene_06's opening ~10s ("What makes this more remarkable is..."), instead of cutting straight to the abstract phylogenetic tree/dots animation, generated a static illustrated "tree of life" image via GPT Image 2 (kie.ai model id `gpt-image-2-text-to-image`) — a glowing bioluminescent tree with bacteria/microorganisms at the roots and jellyfish/anglerfish/squid nestled in the branches — then animated it 10s via Seedance 1.5 Pro (kie.ai model id `bytedance/seedance-1.5-pro`, image-to-video via `input_urls`, Cloudinary used as the public-URL bridge for the input image, no audio). Output: `002_Content-Creation/Video_Editor/002_Channels/001_Anomalous-Wild/001_Bioluminescence-Weapon/_tests/intro_tree_of_life/tree_of_life.png` + `tree_of_life_animated.mp4`.

This is a second data point (alongside the dots-and-lines critique above) that abstract-only opens are the weak pattern generally, not just in the one scene already fixed.

Do not build or formalize this yet — Tony explicitly said hold off on writing scripts or duplicating the GPT-Image-2 → Seedance-1.5 pattern into a reusable tool. This is a noted direction for when the Vox-style asset pipeline (see orchestrator note above) actually gets locked in.

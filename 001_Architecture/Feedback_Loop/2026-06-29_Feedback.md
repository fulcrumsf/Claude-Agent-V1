# Feedback Log — 2026-06-29

## [HARD RULE] Never Loop Video Clips
**What happened:** Proposed looping 5s clips to fill longer beatmap slots (e.g., loop a 5s clip to 12s). Tony stopped this immediately.
**Rule:** Video clips must NEVER loop. Looping is immediately visible to viewers — motion resets, the scene jumps. It is always wrong.
**Correct approach:** Generate at the required duration from the start. If the clip is too short, re-generate it at the correct duration. There is no valid workaround.

---

## [RULE] Always Generate Video With Padding
**What happened:** Tony established that every video generation should include at least 1 second of padding beyond the target final duration.
**Rule:** `generate_duration = max(4, ceil(target_final_duration_s + 1))`
**Why:** Gives real generated footage to trim from. Without padding, a clip generated at exactly the target duration may end awkwardly or cut content.
**Applied to:** `batch_generate_videos.py` — now computes per clip from beatmap.

---

## [RULE] Script Must Read Beatmap — Never Hardcode Duration
**What happened:** `DURATION = 5` was hardcoded in the generation script. The beatmap had `target_final_duration_s` values up to 12s. The script ignored those values, generating 5s for everything.
**Rule:** Generation duration must always be derived from the beatmap's `target_final_duration_s` per clip, plus padding. No hardcoded duration ever.
**Why:** The beatmap is the source of truth for timing. Hardcoding creates a silent mismatch that is only discovered when trying to assemble the video.

---

## [RULE] Read Existing Files Before Planning
**What happened:** Was planning the video assembly as if the beatmap and shot list didn't exist yet. Tony said: "You're assuming we don't have any of this."
**Rule:** Before planning any step in a production pipeline, check what files already exist. Read Beatmap.json, Shot_List.md, existing Video_Clips/, etc. Never assume files are missing.
**How to apply:** At session start on any production task, read the production folder structure and key data files first. Plan from what actually exists.

## [RULE] Beatmap Clip Duration Hard Limits
**What Tony said:** "Each beat really shouldn't be longer than eight seconds... people are going to get bored. Ideally each video clip should be three to six seconds."
**Rules:**
- Hard limit: `target_final_duration_s` ≤ 8 seconds per clip in any beatmap
- Ideal range: 3–6 seconds per clip
- These limits apply to ALL future Reimagined Realms productions
- This Pompeii video violates it (Act 3 clips are 12s each) — acceptable for now but flagged for revision

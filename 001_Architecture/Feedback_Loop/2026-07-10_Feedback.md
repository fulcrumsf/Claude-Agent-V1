## Diagram/callout color: brand accent ≠ automatically correct — sample the actual image instead

**Context:** Rebuilding the anglerfish esca/bacteria callout clip (Anomalous Wild, Bioluminescence Weapon, ~2:32) after the original image-model-baked labels came out as gibberish. **Correction:** Tony pointed out that documented brand colors are for channel chrome (logo, thumbnail, lower-thirds) — not automatically right for in-scene diagram graphics layered over generated illustration content that isn't itself "branded." Told me to pull color from the image itself, or default to white-on-black high contrast per the reference example provided.

**What I did about it:** Sampled `Fish-01.png` directly with PIL near the callout targets — came back electric cyan (`rgb(19,245,251)` ≈ `#13F5FB`), which also happens to match the channel's *other* documented accent ("Accent Cyan — glitch cuts/anomaly reveals"), so the fix was "pick the right accent for the job and verify against real pixels," not "throw out the brand system." Rendered the corrected clip with white label text + cyan (image-sampled) leader lines.

**Also confirmed (not a correction, a validated preference):** Tony explicitly liked the callout reveal style — leader lines drawing in, label text phasing in with a glow/blur-resolve rather than a flat opacity pop. Locked this in as the default reveal pattern for future callouts.

**Made durable, not just remembered:** Wrote both as dated, additive rules in a new file `002_Content-Creation/Video_Editor/003_Remotion/src/skills/design-rules-learned.md`, wired into the Remotion app's own skill-detection system (`003_Remotion/src/skills/index.ts`) so the AI motion-graphics classifier picks it up automatically, and pointed to it from `Video_Editor/CLAUDE.md` and `Anomalous_Wild_Video_Pipeline/SKILL.md`. Flagged (not fixed) that `DiagramLabels.tsx` still hardcodes brand green as its default line color — a known gap for a future session, left alone per "don't touch what's already locked in without asking."

**Why this matters going forward:** Tony wants the video pipeline to accumulate its own design judgment from feedback across iterations, not just have me recall it in-session. The `design-rules-learned.md` file is meant to be the durable, additive home for that — check it before any future overlay/callout/diagram styling decision, and add new dated entries rather than overwriting old ones.

## Follow-up correction, same session: label placement (not just color)

After the color fix, Tony had me screenshot the rendered clip's last frame and diagnose it myself before he weighed in — self-caught the crossed-lines/crowded-labels problem but didn't yet have the actual fix. Tony then supplied `Fish-02.png` again as the explicit reference: labels belong fully off the subject in open black space, only a dot touches the subject, and multiple labels should approach from different directions so lines never cross. First implementation had derived label position as a small fixed offset *from* the target dot, which kept both labels crowded on the glowing subject itself. Fixed by making label position an independent anchor chosen in verified-empty background space (sampled pixels to confirm black), with one label anchored above the fish and one below. Re-rendered and visually matches the reference layout. Logged as Rule 3 in `design-rules-learned.md`.

## Second follow-up, same session: parallel lines are still a weak composition

Rule 3's fix (one label above, one below) was non-crossing but both lines were near-vertical and mirrored — Tony called this out as still not good composition, wanted ESCA's line up-and-right and the bacteria line down-and-far-left instead. Asked directly whether a real external skill/reference exists for motion graphic design principles rather than just my own inference. Web-searched and found the first result was the wrong genre (patent/technical-drawing convention: uniform parallel callout lines — actually contradicts what was needed here). Second, more targeted search (medical/anatomical diagram radial labeling literature) confirmed the real principle: leader lines radiating from one cluster should not be parallel to each other, slope should vary by radial position. Repositioned both label anchors to diagonal, non-parallel angles; re-rendered; matches. Logged as Rule 4 with citations in `design-rules-learned.md`.

**Process lesson:** when asked to ground a design decision externally, the first search result isn't automatically the right one — checked genre-fit (is this patent-drawing convention or explainer-video convention?) before applying it, and searched again with a more specific query when the first result didn't match the reference image Tony had already provided.

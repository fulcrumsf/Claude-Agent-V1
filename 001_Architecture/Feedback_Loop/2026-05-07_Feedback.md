## Two-part OpenAI history / image library model
- Tony wants conversation history and the visual asset library kept separate.
- `OpenAI_history` should hold the conversation `.md` layer and image references/links.
- `Obsidian_Attachments` should hold the actual images plus context notes for visual search like "pull up all my t-shirt designs".

## Duplicate handling preference
- Tony does not want already-ingested duplicates churned again during review-layer cleanup; if a file is already represented in the canonical set, it should effectively be a no-op.

## Conversation shard handling
- Tony wants raw `conversations-*.json` export shards treated as already ingested once the theme-note layer exists for every conversation, and wants `Multiple Conversations in One` available only as a fallback for unsplittable future bundles.

## Image ingestion proof
- Tony wants image ingestion to be verified against the canonical `Obsidian_Attachments/OpenAI_Images` hashes so exact duplicates are not reprocessed.

## Note-link matching rule
- Tony wants uncategorized conversation notes checked against the canonical attachment links, but not treated as raw `Needs Ingestion` matches unless the underlying file actually exists there.
- Filename-only comparisons are not sufficient for the image routing workflow; the canonical attachment folders are the source of truth for linked assets.

## N8n filename bucket
- Tony wants obvious N8n workflow screenshots grouped automatically by filename into a dedicated `N8n-Screenshots` bucket so they can be bulk-reviewed or deleted later without manual per-file inspection.

## Keyword-based raw image grouping
- Tony wants repeated filename words to drive automatic grouping of raw images in `OpenAI_history/Needs Ingestion` so obvious clusters like screenshots, typography, framing, and generated images can be sorted without opening every file.

## Workspace map maintenance
- Tony wants the workspace map updated any time new folders or structural files are introduced, with a brief explanation for each folder.

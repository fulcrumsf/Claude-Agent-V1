# Feedback Loop — 2026-10-13

## Real data over LLM-opinion scoring, enforced hard

Tony's exact correction on the first revenue-stream scoring pass: "What you're giving me back is what your LLM is just telling you to give me back. The real data I want is analytics." He wanted connectors used, live dashboards pulled, and every market claim cited to a real source — not a plausible-sounding 0-100 score.

**Why it matters:** this is a repeat/escalation of the existing `feedback_verify_before_presenting` pattern (grounded ≠ verified), but stronger — it's not just "verify your own output," it's "don't score anything from priors at all, go get the number." Applies to any scoring/ranking task, not just this one.

**How to apply:** when asked to score, rank, or compare business options, default to live data pulls (dashboards, APIs) and cited web research before writing a single number. If a number can't be grounded, say so explicitly in the output rather than estimating silently.

## Existing tooling ≠ permission to reuse it as the new pipeline

Tony corrected a pipeline draft that pointed directly at his existing n8n workflows as the build target: "I don't want to use those N8n workflows... we could use those as a basic guideline for the architecture." Some of the Python scripts may be reusable; which ones is still open.

**Why it matters:** finding existing automation for a stream doesn't mean the plan should wire it up as-is. Scattered prior work (n8n workflows, a year-old ChatGPT research session, Python scripts) is reference material for a rebuild, not a finished pipeline to point at.

**How to apply:** when consolidating prior research/automation into a plan, frame it explicitly as "reference architecture" unless the user confirms reuse. Don't assume "it already exists" means "reuse it."

## "Too much detail for one session" is a valid stop, not a prompt to keep digging

When asked to walk through how the full Ikigai pipeline fits together, Tony said plainly: "I'm not walking you through how it all fits together. It's too much detail for me to give you in this session." No further probing was wanted — just log it as deferred and move to what could be answered (skills/tools research, mockup pattern observation, PhotoCraft).

**Why it matters:** matches `feedback_explicit_over_automatic` — don't keep pushing on a thread the user has explicitly closed, even if it seems incomplete from the agent's side.

**How to apply:** when a user declines to elaborate and names the reason (too much detail, not now), stop immediately, mark it open/deferred in the relevant file, and route to adjacent, answerable sub-tasks instead.

**How to apply:** if Agent tool spawning is denied with a "Self-Modification" or similarly generic reason unrelated to task content, treat it as a session-level capability gap, not a signal to rephrase and retry. Proceed with direct execution.

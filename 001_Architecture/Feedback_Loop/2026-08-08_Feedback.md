## Text must never cover image content on composited reference sheets

**Correction:** On reviewing the regenerated Roman Gladiator Prop Sheet (`Prop_Sheet_v2.png`), Tony flagged that panel labels/captions must never overlap or cover the actual image content — this applies to any composited sheet with text labels (prop sheets, environment sheets, contact sheets).

**Why it matters:** A label covering part of a prop/scene panel makes that panel useless as a visual reference — the whole point of these sheets is to be a clean, complete reference the model or a human can read from.

**How to apply:** Next POV Pipeline v2 update — audit every module that composites text onto a generated image (`prop_sheet_generation.py`, `environment_sheet_generation.py` prompts that ask GPT-Image-2 to render labels directly on the sheet, and `storyboard_generation.py`'s `compose_contact_sheet()` PIL compositing) and ensure labels are always placed in dedicated caption space below/beside each panel — never overlaid on top of the image itself. For AI-generated in-image labels (prop/environment sheets), this may mean instructing the model to reserve a blank margin per panel for the label rather than assuming it won't overlap.

**Status:** Applied 2026-08-08 — added an explicit reserved-margin instruction to `prop_sheet_generation.py` and `environment_sheet_generation.py`'s prompts ("the label must never overlap or cover any part of the panel's own image content"). `storyboard_generation.py`'s `compose_contact_sheet()` was already compositing captions into dedicated space beneath each panel, not overlapping — no change needed there. Confirmed working on regenerated `Prop_Sheet_v3.png`.

## Image QA must check whole-composition perspective/physics, not just whether each described element was included

**Correction:** Reviewing Roman Gladiator Scene 13 v2, Tony pointed out the image still reads as the character lying on the ground even though the prompt correctly specified "standing, arm raised in triumph, looking straight up." His diagnosis: this is a perspective/foreshortening problem, not a missing-element problem — the extreme upward camera angle combined with the raised arm thrust toward the lens renders as a thigh-proportioned, foreshortened shape that visually reads as a raised leg, making the whole pose look like lying down even though every individual instruction was technically followed.

**Why it matters (this is about my own review process, not just prompting):** when I review a generated image, checking "does this contain what I asked for" is not the same as checking "does this actually look right as a whole shape/composition." Tony explicitly said reviewers need to look for physics and perspective problems, not just confirm requested elements are present — my first pass at critiquing Scene 6 (the "duplicate body" misdiagnosis) and this Scene 13 case are both instances of the same gap: analyzing regions/elements individually instead of evaluating the whole rendered composition against real-world plausibility.

**How to apply:** When reviewing any generated POV image going forward, explicitly ask "what does this look like as a whole shape, ignoring what I was trying to get it to show" before concluding it matches the prompt. Locked into `POV_Style_Guide.md`'s new "Perspective-distortion / foreshortening check" — also fixed at the prompting level: when a gesture requires extreme foreshortening (a limb thrust near-straight at the camera), substitute the reaction it's meant to produce (e.g. a cheering crowd) instead of forcing the foreshortened limb into frame.

**Status:** Applied immediately — checklist item added to `POV_Style_Guide.md`; Scene 13 being regenerated now with the crowd-reaction framing instead of the raised-arm-into-sky framing.

## Prop sheets need explicit left-hand and right-hand "held" panels, not one generic held panel

**Correction:** Reviewing Roman Gladiator Scene 8 v2, Tony flagged that the Scutum Shield's thumb orientation was wrong for the hand holding it (he's holding it in his left hand, but the thumb read as if it were a right hand's grip). The shield is always held in one specific hand by convention (left, since the sword arm is right), and the current `prop_sheet_generation.py` only generates one generic "Held from POV" panel per prop with no hand specified — leaving the model to guess (or misapply) which hand's grip anatomy to render, the same underlying laterality-guessing problem as the Scene 6 handshake issue, just applied to a single-hand grip instead of a two-person contact point.

**Why it matters:** A prop that's always carried in a specific hand (shield = left, sword = right) needs its "held" reference panel to explicitly show that exact hand's grip anatomy (thumb/finger wrap direction), not a generic/ambiguous hand — otherwise every scene using that prop inherits the same 50/50 chance of getting the thumb backwards.

**How to apply:** Next POV Pipeline v2 update — extend `prop_sheet_generation.py`'s prop schema so a prop can specify `held_left` and/or `held_right` (instead of, or in addition to, one generic `held`) with its own description, each producing its own explicitly labeled panel (e.g. "Scutum Shield — Held from POV (Left Hand)"). Props that are only ever held one specific way (shield=left, sword=right) only need that one labeled panel, but it must say which hand.

**Status:** Applied 2026-08-08 — `prop_sheet_generation.py`'s schema now takes `held_left`/`held_right` instead of a generic `held` field, each producing its own explicitly-labeled panel. Roman Gladiator's `Props.json` updated and `Prop_Sheet_v3.png` regenerated with "Held from POV (Left Hand)" / "(Right Hand)" panels for the Shield, Sword, and Arm Guard. 8/8 tests updated and passing, `validate_build.py` clean.

- Build bugs found and fixed during setup and real-use testing:
  1. `xr_xero_api.py`'s `TOKEN_URL` was `https://identity.xero.com/oauth/token` (wrong — Xero returned its login HTML page instead of JSON); corrected to `https://identity.xero.com/connect/token`.
  2. `xr_secrets.py`'s env-secrets parser didn't strip a leading `export ` token, so it couldn't read this workspace's actual `export KEY=value` convention in `~/.env-secrets`.
  3. `xr_match.py`'s `byte_evidence()` only accepted extraction `confidence == "text"` (true PDF text), silently rejecting `"ocr"` confidence — meaning every screenshot/image receipt got `sha256: null` and would ALWAYS fail hash verification after upload, no matter how correct the image was. Fixed to accept both, while adding an explicit `confidence == "text"` requirement to the separate `auto_eligible` gate in `classify()`, so OCR'd screenshots can now be hash-verified and archived once a human approves them, but still can never silently auto-attach on their own (OCR can misread a digit; PDF text extraction can't).
  4. (2026-10-10, found via real live-attach test) `attach()`'s "already attached, hash matches" branch correctly avoided a duplicate upload but left the item in the terminal `already_attached` state, which `archive()` never processed (it only looked at `verified`) — so the local file was never moved to `Archive/`, and a later run couldn't pick it back up either, since `fetch()` already excludes transactions Xero reports as having an attachment. Fixed: `already_attached` now flows into `archive()` too (both in `run()` and the standalone `archive` command), and `xr_state.py`'s transition table allows `already_attached -> archived`/`verified_not_archived`. This was a real gap, not a sandbox artifact — same code path in production.
- **Open planning inconsistency (not fixed, left as locked):** `config.example.json`'s `intake_dir`/`archive_dir` are relative paths (`000_Ingest/Xero_Receipts`), which only resolve correctly when the command is run with the Agent-OS root as the working directory. But `Weekly_Run_Prompt.md` step 1 says to `cd` into the tool's own promoted folder first — from there, those same relative paths would NOT resolve to the real `000_Ingest`. C07 (a locked acceptance check) pins these exact relative strings, so this could not be fixed here without touching `Acceptance_Checks.json`, which `/lab-run` never touches. Until Tony decides (via `/lab-plan` revision or an explicit override), every real run must either run from the Agent-OS root, or pass `--intake-dir`/`--archive-dir` with absolute paths explicitly (confirmed working: `--intake-dir "/Users/tonymacbook2025/Documents/Agent-OS/000_Ingest/Xero_Receipts" --archive-dir ".../Archive"`).

## What went well

- **The "prove it before you build it" discipline paid off directly.** Every fix folded into the pipeline this session (prop sheet hand-specificity, environment sheet people-less rules, storyboard sheet_labels, the scene-writing checklist items) traced back to a real failure caught during manual, one-off tool calls on Roman Gladiator and Titanic Stoker before any code was touched. Nothing was speculative. This is the second session in a row this pattern held up — worth continuing to default to it for any future pipeline architecture change.
- **Caught my own bug via research, not assumption, on the video-prompt laterality question.** When Tony asked whether hand-laterality language would confuse Seedance's video prompting, I ran actual searches on image-to-video prompting best practices rather than guessing, and the answer (don't re-describe static details already in the first frame) was both correct and directly useful — it became a real, cited addition to the Seedance-Prompting-Guide.
- **The `first_frame_url`/`reference_image_urls` mutual-exclusivity bug got fixed fast once it surfaced**, because I had the discipline to actually run all 13 video generations for real rather than trust the code compiled cleanly. Tony's correction ("the first frame is the reference — didn't we talk about this before") was a fair callout: I had re-added a second consistency mechanism without checking whether the sheet-driven image stage had already made it redundant. That's a reasoning gap, not a tooling gap, and worth remembering: when a system was explicitly designed to solve a problem once at one stage, don't reach for a second mechanism to solve the same problem at a later stage without checking first.

## What went wrong / what to watch

- **The YouTube "top 10" mistake is the clearest lesson from today.** I used `search.list?order=viewCount`, which is an approximate/algorithmic ranking, not an exact sort, and it silently dropped a video that belonged in the true top 10. Tony caught this by cross-referencing against YouTube Studio — I did not catch it myself, and had no internal check that would have caught it (I never verified the search-based ranking against an exact sort). **Lesson: any API result described as "order by X" without an explicit guarantee of exactness should be treated as approximate by default — verify by fetching the full dataset and sorting locally, especially before presenting a ranked list as fact.** This is the same category of error as trusting `--help` output over a real API call (the `first_frame_url`/`reference_image_urls` bug from earlier the same session) — an unverified assumption about how a third-party API actually behaves, stated with more confidence than the evidence supported.
- **My first visual critique of a generated image (Scene 6) was wrong, and confidently so.** I diagnosed "a duplicated body/impossible head visibility" when the actual problem was hand-laterality/thumb mismatch. Tony had to correct me and then walk me through what I was actually looking at. This wasn't a research-skippable error — it was a visual-reasoning error, pattern-matching a plausible-sounding but incorrect explanation instead of carefully tracing what each shape in the image actually was. **Lesson: when critiquing a generated image, describe the specific pixels/shapes first, then form a hypothesis — don't jump straight to a category of known-failure-mode and retrofit the image to match it.**
- **Small process friction: Suno's 500-character prompt limit in non-custom mode wasn't known until a real API call failed.** Cheap to fix once discovered (kie-cli's own `--help` documents it clearly), but worth generalizing: before writing a long descriptive prompt for any generation API, a quick `--help` check for length limits would avoid a wasted round-trip. Low-severity, but it's the third time this session a `--help`/schema check before-the-fact would have saved a failed call after-the-fact (Suno prompt length, Seedance mutual-exclusivity, Instagram's 5-hashtag cap).

## Recurring pattern to keep watching

Every real failure this session that wasn't a design/scope decision traced back to the same root cause: **treating a third-party tool's documented interface, cached data, or approximate ranking as more precise/complete than it actually is**, discovered only after a real call failed or a real cross-check caught it. kie-cli's `first_frame_url`+`reference_image_urls` combination, YouTube's `order=viewCount`, Suno's prompt length cap, Instagram's hashtag cap — four instances in one session. None of these were catastrophic, and Tony's own project rules already say "verify tool behavior against the tool's actual source before trusting a workspace doc's claim about it" — the gap is that this hasn't yet generalized to live third-party API responses/limits, only to internal docs. Worth explicitly extending that rule: **before relying on any parameter combination, sort order, or limit from a third-party API for the first time, either check the tool's own `--help`/schema output for explicit constraints, or make one cheap real call to confirm — don't infer from what the interface merely allows you to pass.**

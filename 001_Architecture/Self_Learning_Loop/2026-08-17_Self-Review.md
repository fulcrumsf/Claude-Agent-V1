# Self-Review — 2026-08-17

## What went wrong
- Repeated a general "looks fine" pass-through on storyboard anatomy review at least twice before Tony caught a real defect (Scene 03 frame 8, single eyestalk) himself. Root cause: reviewing for overall plausibility instead of mechanically counting discrete anatomical features (eyes, claws) per frame against the character sheet. General visual review is not equivalent to a count-check — I only adopted the count-check discipline after being corrected, not proactively.
- Defaulted to a "surgical patch" instinct — fixing individual flagged frames while leaving the surrounding concept nearly identical — until Tony explicitly rejected that approach twice and required full concept-level rework instead. The underlying belief was that minimizing changed surface area is inherently lower-risk; in a generative-image context that's backwards, since the frame set needs internal visual consistency and coherent shot logic, not just per-frame correctness.
- Wrote Scene_08's frame_actions list without first checking it against `compute_frame_count(duration_s)` — submitted 12 actions for an 11-frame scene and only caught it because `build_spec()`'s own guardrail raised a `ValueError`. The math (round(14/1.25)=11) was cheap to check up front; I didn't check it until the call failed.
- The claw "teeth/mouth" artifact appeared identically in Scene_06 and then again in Scene_07, generated from the same character sheet, before I flagged it as a systemic pattern rather than two unrelated one-offs. Should have generalized after the first occurrence and preemptively added the same negative-anatomy language to Scene_07's prompt instead of only fixing it after Tony pointed out both instances himself.

## What worked well
- Once the frame-by-frame count-check methodology was adopted (count eyes per panel, cross-reference camera angle to explain legitimate single-eye shots vs. real errors), it reliably caught real defects and correctly cleared good frames — including distinguishing an intentional extreme-macro single-eye push-in (Scene_08 frame 1) from an actual missing-eye error, once the ambiguity was called out and the prompt language was tightened to make the crop unambiguous (showing carapace edge at frame border).
- Writing explicit negative anatomy language directly into frame_actions ("smooth hinged claw, NOT a mouth, NOT teeth, NOT a duplicate claw shape") fully eliminated the artifact on regeneration in one pass, vs. vaguer "correct anatomy" phrasing that had let it through originally. Concrete negatives outperform general correctness instructions for this generation pipeline.
- Locked what was learned this session into the reusable skills (Storyboard-Generation, Character-Sheet-Generation, Anomalous_Wild_Video_Pipeline) rather than only patching this one production — future channels/productions inherit the shot-variety cadence rule, the mandatory anatomy count-check, and the anatomy_notes character-sheet pattern without re-discovering them.
- Held the "do not move until told" discipline throughout — presented the eye-count/claw-artifact findings and waited for Tony to scope which scenes to touch (Scene_06 + Scene_08 only, explicitly not 05B) before regenerating anything.

## What keeps recurring
- This is now a repeated pattern in this workspace: an initial "looks fine" pass misses a real defect that only a specific, mechanical count-check (not general plausibility review) catches. Worth treating per-feature counting as the default first-pass QA step for any character-sheet-referenced creature content, not something to rediscover per production.
- An artifact traced to one character sheet showed up in more than one downstream storyboard scene before being treated as systemic. When a generation defect repeats across two+ independently-generated outputs that share the same reference image, the working hypothesis should shift toward "the reference image itself may be ambiguous in this region" rather than only patching each downstream prompt — worth checking whether the Mantis_Shrimp_Main_Character_Sheet.png's claw panel itself reads ambiguously (could explain why GPT-Image-2 keeps interpreting it as a mouth).

## Could be automated
- The frame-count-vs-`compute_frame_count()` guardrail in `build_spec()` did exactly its job today — it caught a bad frame list before any API spend. No change needed there; noting it as a case where an existing automated check worked as designed.
- The root cause of the original eye-count bugs (singular anatomical language like "the eye" in frame_actions) is a pattern that could be caught by a lightweight static linter over `frame_actions` before generation — flag singular anatomical nouns for known multi-part features (eyes, claws) so the writer catches it before spending an API call, rather than catching it only on visual review after the image exists.

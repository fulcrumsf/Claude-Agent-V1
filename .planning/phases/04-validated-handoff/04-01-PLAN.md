# Plan 04-01: Build Validated Seedance Handoff

## Objective

Build a handoff manifest and Seedance prompt builder that can operate only from a selected passing storyboard result.

## Requirements Covered

- HANDOFF-01
- HANDOFF-02
- HANDOFF-03

## Must Haves

1. Missing, failed, manual-review, or unselected storyboard results are rejected before prompt construction.
2. The generated prompt follows the existing five-section Seedance contract in order.
3. Action beats are derived from validated frame observations with chronological physical cause and observable result.
4. The handoff preserves candidate image, spec, QA report, and hash references.
5. Storyboard references are represented separately from clean first-frame assets.

## Tasks

### Task 1: Define the handoff manifest
- Add a provider-neutral manifest validator beside the storyboard tools.
- Require selected attempt identity, QA status, active storyboard path, contract path/hash, and reference-role metadata.
- Refuse manifests with `status != pass` or without a selected candidate.

### Task 2: Build the Seedance prompt adapter
- Convert validated frame observations and contract locks into camera, continuity, action, audio, and hard-constraint sections.
- Preserve the existing Seedance prompt contract and avoid literal panel reproduction instructions.
- Require exact prompt persistence before downstream submission.

### Task 3: Add tests
- Test handoff rejection for missing, failed, manual-review, and unselected results.
- Test chronological action output from Shot 6 evidence.
- Test separate reference-image and first-frame fields.
- Test prompt section order and required-content validation.

## Dependencies

- Phase 2 QA report schema.
- Phase 3 selected-candidate state and archive behavior.
- Existing Seedance prompt contract and pre-video gate.

## Verification

- Focused Neon Parcel tests with no provider calls.
- Render and inspect a Shot 6 Seedance handoff prompt.
- Run Python compilation and `git diff --check`.

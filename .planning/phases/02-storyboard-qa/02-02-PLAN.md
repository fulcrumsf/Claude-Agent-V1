# Plan 02-02: QA Evidence Review Gate

## Objective

Make the Phase 2 QA output usable as a hard gate by documenting the evidence checklist and verifying that no ambiguous result can be interpreted as a pass.

## Requirements Covered

- QA-01
- QA-02
- QA-03

## Must Haves

1. Each checklist item maps to a required field in the normalized QA result.
2. Findings are actionable enough to guide a later regeneration prompt.
3. The result explicitly records the difference between image evidence and prompt/schema intent.
4. The downstream contract is documented as `status == pass` only.

## Tasks

### Task 1: Cross-check evidence coverage
- Compare the evaluator output to `01-ACCEPTANCE-CHECKLIST.md`.
- Identify any requested check that the chosen vision response cannot establish reliably.
- Mark those checks as ambiguous/manual review rather than guessing.

### Task 2: Add a human-readable report
- Provide a compact report renderer for review logs.
- Include candidate path/hash, contract path/hash, status, confidence, and frame-specific findings.

### Task 3: Verify Phase 3 handoff
- Document the exact input/output boundary Phase 3 will use.
- Ensure a failed or manual-review result contains enough information to improve the next prompt without rewriting the original contract silently.

## Verification

- Test report output for pass, fail, and manual-review results.
- Test that missing evidence cannot render as a passing report.
- No provider or paid generation calls.

# Plan 02-01: Build Storyboard Vision QA

## Objective

Create a provider-neutral storyboard QA evaluator that compares a generated sheet with the Phase 1 contract and emits actionable, fail-closed evidence.

## Requirements Covered

- QA-01
- QA-02
- QA-03

## Must Haves

1. A typed/validated QA result records candidate identity, contract identity, status, confidence, checked frames, and findings.
2. The evaluator checks per-frame subject presence/count, object state, spatial relationship, action/state, and exact caption.
3. The evaluator checks adjacent-frame transitions, chronology, camera/geometry continuity, and physics plausibility.
4. Any missing, malformed, contradictory, or low-confidence provider result fails closed or routes to manual review.
5. Unit tests use mocked vision responses and include the Shot 6 gate/subject failure pattern.

## Tasks

### Task 1: Define the QA result schema
- Add a module beside `storyboard_contract.py` with explicit status and finding structures.
- Require frame/panel references, category, severity, evidence, confidence, and recommendation for every finding.
- Validate provider output before treating it as evidence.

### Task 2: Define the vision adapter boundary
- Add a small interface/function boundary accepting the candidate image and structured contract.
- Build the inspection prompt from the same frame requirements, including adjacent-frame comparisons and fail-closed instructions.
- Keep provider credentials, HTTP calls, and response parsing out of the deterministic evaluator.

### Task 3: Implement strict evaluation
- Normalize the provider result into the QA schema.
- Require every requested check to have an explicit result.
- Treat any failed required check as `fail`; treat ambiguity/insufficient evidence as `manual_review` and not as a pass.
- Preserve enough raw/evidence metadata for later audit without storing secrets.

### Task 4: Add regression tests
- Test a passing mocked candidate.
- Test absent bear/wrong gate state in Shot 6.
- Test broken adjacent transition and implausible physics.
- Test caption mismatch, missing panel evidence, malformed provider JSON, and low confidence.
- Verify no network/provider call occurs in unit tests.

## Dependencies

- Phase 1 `storyboard_contract.py` and Shot 6 fixture.
- Phase 1 acceptance checklist.
- Existing vision-analysis conventions in `001_Architecture/Tools/AI-Analysis/`.

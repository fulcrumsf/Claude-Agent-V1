# Plan 03-02: Wire Candidate Generation and QA Loop

## Objective

Connect the attempt controller to injectable storyboard-generation and Phase 2 QA callbacks while keeping provider failures, QA failures, and manual review auditable.

## Requirements Covered

- REGEN-01
- REGEN-02
- REGEN-03
- REGEN-04

## Must Haves

1. The loop generates exactly one candidate, evaluates it, and stops immediately on pass.
2. Failed candidates produce targeted retry context without changing the original structured contract.
3. The loop stops after three failed/ambiguous candidates and emits a manual-review flag.
4. The loop does not invoke any Seedance path when no candidate passes.
5. Provider exceptions produce a distinct retryable/provider-failed record and do not masquerade as QA results.

## Tasks

### Task 1: Define adapter interfaces
- Accept injectable `generate_candidate(spec, attempt, retry_context)` and `evaluate_candidate(spec, image)` callbacks.
- Keep the orchestrator independent of GPT-Image-2, kie.ai, and network credentials.

### Task 2: Implement the loop
- Reserve and persist an attempt before generation.
- Persist the image and QA result after each callback completes.
- Build the next retry context only from recorded findings.
- Return a selected candidate or a blocked/manual-review result.

### Task 3: Add integration tests
- Simulate fail/fail/pass and verify it stops at candidate three.
- Simulate fail/fail/fail and verify the downstream callback is never called.
- Simulate provider failure and verify it is logged distinctly.
- Simulate a passing first candidate and verify no unnecessary second call occurs.

### Task 4: Document operational invocation
- Document the dry-run/test invocation and production boundary.
- State that live provider calls require the existing tool-manager routing and paid-generation approval gates.

## Dependencies

- Plan 03-01 attempt controller.
- Phase 2 QA evaluator and report schema.

## Verification

- Run all focused Neon Parcel tests.
- Run a fully mocked loop with zero network access.
- Confirm all failed candidates remain archived and only a passing candidate can be returned as active.
- Run Python compilation and `git diff --check`.
